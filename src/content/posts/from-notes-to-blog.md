## 为什么要发布笔记

笔记写给自己看，博客写给世界看。但两者不应该是割裂的——最好的博客就是**整理过的笔记**。

Obsidian 的 Markdown 原生特性让"笔记→博客"的转换几乎零成本。你只需要解决一个问题：如何把 `[[WikiLink]]` 变成站内链接。

## 转换的核心问题

### 1. Frontmatter

博客文章需要元数据：标题、日期、标签、封面图。在 Obsidian 笔记开头加上 YAML frontmatter 即可：

```yaml
---
title: "文章标题"
date: "2025-05-01"
tags: ["标签1", "标签2"]
cover: "https://example.com/cover.jpg"
excerpt: "一句话摘要"
draft: false
---
```

### 2. WikiLink 转换

Obsidian 用 `[[笔记名]]` 链接，博客需要转成标准 URL。这正是本博客系统做的事——自动把 `[[Obsidian入门指南]]` 转成可点击的站内链接。

### 3. 附件引用

Obsidian 的 `![[图片名.png]]` 需要转成标准 Markdown 图片语法 `![](url)`。本系统对无法解析的内嵌图片会降级为占位图。

## 保留的核心体验

发布为博客后，以下 Obsidian 特性得以保留：

- **双链跳转**：`[[WikiLink]]` 变为站内链接，点击即跳转
- **反向链接**：文章底部展示"哪些文章引用了本文"
- **知识图谱**：专门的图谱页面可视化所有文章间的链接关系
- **代码高亮**：支持 180+ 语言
- **数学公式**：KaTeX 渲染行内与块级公式

## 发布工作流

结合 [[知识管理工作流]] 的四步法，发布是第五步：

1. **捕获** → 每日笔记
2. **整理** → 主题笔记
3. **链接** → `[[WikiLink]]`
4. **回顾** → 图谱检查
5. **发布** → 加 frontmatter，同步到博客

## 技术实现要点

本博客系统的 Markdown 渲染管线：

```
.md 文件 → frontmatter 解析 → WikiLink 转换 → GFM 扩展 → 代码高亮 → 数学公式 → HTML
```

每一步都是独立可替换的模块。如果你想了解 Markdown 语法细节，参考 [[Markdown语法速查]]；想看代码高亮效果，参考 [[代码高亮的艺术]]；想看公式渲染，参考 [[用数学公式美化笔记]]。

## 图谱的迁移

Obsidian 的图谱视图在博客中变成了**公开的知识地图**。访客可以通过 [[图谱思维与知识网络]] 中描述的方式，探索你的文章间的关联。

这在传统博客中是做不到的——因为传统博客没有双链。这也是为什么 [[双链笔记的哲学]] 如此重要：它不仅改变了你写笔记的方式，也改变了读者浏览博客的方式。

## 总结

从笔记到博客，不是"搬运"，而是"开放"。你的个人知识网络，从此可以被世界看见。
