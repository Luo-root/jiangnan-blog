# v0.1.1 — 功能验证收尾，使用中打磨

> 状态：计划（未发版）  
> 基线：`v0.1.0`（tag `a4a41c8`）  
> 不是新架构。不换协议、不引向量、不引入 DSH 运行时。

MCP 现在的问题不是「缺一种插件形态」，是 **Agent 还没有把它当记忆基座用熟**。v0.1.1 只做两件事：把 v0.1.0 里代码在、生产没走过的路径走一遍；在真实会话里改操作环和摩擦。更大的「控制中心 / 博客切割」见 [`roadmap.md`](roadmap.md)，**不进本小版本**。

---

## 做什么

### A. 验证收尾（先证真，再谈优化）

这些在 v0.1.0 **不是假实现**（有代码、有单测），但主路径没人用过。没证据之前，不准当「已经好了」。

| # | 要验证什么 | 怎样才算过 | 若失败 |
|---|---|---|---|
| 1 | Proposal 批准真写 Vault | 批准一条 → 目标 `.md` 变了 → git commit 在工作台仓库 | 只改 status = 修 apply，不算 v0.1.1 完成 |
| 2 | 3-way 冲突可看见、可救 | 造一条 stale/正文冲突 → `conflict` + 详情红绿 diff；换 base 或改 payload 后再批 | 冲突被静默覆盖 = 修，不准当成功 |
| 3 | MCP get 打出热度 | `knowledge.get` / `skill.get` 后 `access_count>0`；后台热度页非空；search `sort=hot` 顺序变 | 仍全 0 = 查 Hit() 是否被后台 get 误伤或根本没走 MCP |
| 4 | WikiLink 反链进搜索分 | 有反链的笔记搜相关词时 `signals.wikilink_backref>0` | 信号永远 0 = 修索引，不先做图谱验证器 |
| 5 | apply 回流 | VPS apply commit 后本地 `git pull vps main --rebase` 能拿到 | 回流断 = 修 hook/权限，不改协议 |
| 6 | Inbox retention | 一条 done/abandoned 过 `retention_days` 后从列表消失 | 没删 = 修；不因此改状态机 |
| 7 | `agent_prompt` 真指导行为 | 问规范 → `skill.list` → `skill.get` 用返回的 `id`；问待办会 `inbox.append` | 只口头说有 skill = 改 `operating-loop.md`（Vault），不必发 MCP 功能 |

Token `grace≠0`、公网 HTTPS：**不做验证阻塞**。grace 默认 0 已够用；HTTPS 等备案。

### B. 使用中打磨（只改摩擦，不改契约骨架）

允许：

- 改 `Workbase/context/operating-loop.md` 和其它 pack（走 `sync.ps1`）
- 改 `agent_prompt` 拼装顺序（仍 SCHEMA §4.6，描述性正文仍从 Vault 读）
- 后台文案、空态、热度空榜说明
- 修验证里暴露的真 bug

不允许（本版本明确 **不做**）：

- 向量库 / Embedding
- DSH / 新宿主运行时
- Inbox 自动轮询执行、子任务调度器
- Skill DAG / `workflow.yaml` / WebUI 拖工具
- Graph Verifier、推理链强制输出
- 博客与 MCP 拆成两个仓库
- 第 21 个 MCP 工具
- 用「v0.2 候选」把上面那些塞进本版

打磨以 Issue 记一条、PR 修一条。没有使用证据的「优化」不开做。

## 不做什么

见上表「不允许」。再强调：

- 不把 MCP 换成别的协议「抬一层」
- 不把 Vault 迁到 Noema 或其它记忆插件
- 不为验证方便关掉 Proposal HITL

---

## 为什么要做

v0.1.0 契约齐了，Agent 刚开始会 `list`→`get`。缺口在 **生产路径没走完** 和 **提示词还要在使用中改**。换宿主、拆仓库、上调度，都解决不了「批准后文件到底改没改」。

---

## 设计理念

- 先证真再加能力。假实现的定义不变：接口 200、目标文件没变。
- MCP 继续当记忆 / 协议层。宿主（MiniMax Code 或以后的 DSH）当会话层。v0.1.1 不换层。
- 操作环是 Vault 事实源，不是 Go 字符串。行为不对先改 md。
- 博客切割是路线图，不是本小版本。
